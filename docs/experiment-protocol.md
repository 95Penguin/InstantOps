# MicroSS 实验协议与下一步

状态：以下为下一阶段建议协议，不表示已经在现有代码中实现。
现有 MicroSS v2 仍训练下一分钟注入开始代理标签，已通过真实小样本流程检查。

## 论文歧义

来源：[InstantOps ICPE 2024](https://research.spec.org/icpe_proceedings/2024/proceedings/p119.pdf)。
第 4 节描述崩溃或超过 99% 的时间出现 500 错误，第 6.3.1 节描述窗口内
99.9% 请求返回错误（举例 503）。原文没有统一这一阈值与统计口径。
RCA 提到 permutation testing 及 top-k 特征置零，未完整交代可逐行还原的采样、
评分和故障事件关联过程。本文档记录本项目的实验选择，不冒充作者实现。

## 建议固定的任务

输入已完成的五个一分钟窗口，预测紧接着的一分钟应用是否失败。
应用失败目标与根因服务目标分开保存。run 注入日志仅作事件注释，不作为特征。

先验证入口请求提取：结合入口服务、调用语义、trace_id 与 span 类型判定。
不能直接把所有 spans 当作独立请求，不能只凭 parent_id 为空断定入口。
以请求完成时间确定状态码归属，明确每个应用入口的统计范围。
为每分钟保存总请求数、错误请求数、覆盖情况及独立崩溃证据。

建议主协议：目标分钟有效入口请求的 5xx 比例 >= 0.999，或有独立应用崩溃证据，
则 y=1。选择所有 5xx 而非仅 500 是本项目的明确选择。0.99 作为预先声明的
敏感性分析；不通过测试集成绩选择阈值。没有请求而又没有崩溃证据时标为未知，
不默认标为健康。记录低请求量窗口，另外报告其影响。

只有入口与时间对齐验证通过，才实现和运行该协议；若证据不足，则继续将当前
实验明确命名为注入开始预测，不能将代理标签改名为应用失败标签。

## 根因关联与归因

将应用失败事件与注入事件分别保留。根据服务、起止时间和故障持续证据关联，
允许注入早于应用失败；延迟规则需在训练/验证数据中确定并冻结。
同一失败涉及多个注入服务时保留候选集合，无法确定关联的窗口单独列出。
注入服务是已知干预位置，不自动证明它造成了每次观测到的应用失败。

先保留可解释的 masking 基础版本：共享预测模型、每次遮蔽一个服务、固定图、
计算失败 logit 下降；标准化后置零表示训练均值替换，不等同于恢复正常。
它解释模型敏感性，不构成因果证明。辅助监督节点头应单独标注，比较有/无
辅助损失的结果。若实现 permutation importance，明确置换维度、参考样本、
随机种子和重复次数，避免打乱其他测试样本引入的信息。
补充 top-k 联合遮蔽评价，记录并列分数比例及排名规则。

## 数据切分与结果报告

当前 70/15/15 时间切分为工程初版。正式实验先识别故障事件及恢复区间，避免同一
事件跨训练/验证/测试；边界附近剔除横跨分区的历史窗口与目标窗口。
训练分区拟合标准化，验证分区选 checkpoint 和预测概率阈值，测试分区只做最终评估。
预测概率阈值与上面的 SLA 标签阈值是两个不同参数。

分别报告窗口级与事件级结果、正例数、PR-AUC/AP、召回、误报率、提前量，
以及 RCA Hit@K/MFR/MAR。RCA 分别报告真失败窗口上的定位能力和经过预测告警
触发后的端到端效果，避免漏报被忽略。固定若干随机种子并报告波动。

## 执行顺序

1. 完成真实入口识别和时间对齐审计，产出带证据的标签表。
2. 实现独立应用失败标签及事件分组切分，再训练当前模型作为基础版本。
3. 在服务器全量检查指标/日志/图覆盖并训练，保留配置、数据版本和结果。
4. 固定协议后再替换特征编码、图、时间编码和 RCA 模块；RCAEval 后续接入。

服务器资源准备与数据完整性检查可以提前进行，正式效果比较应在标签协议固定后进行。
